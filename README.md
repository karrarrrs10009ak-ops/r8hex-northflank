# R8HEX — Northflank + GitHub

نسخة أولية من المشروع أُعدّت لتُرفع إلى مستودع GitHub وتُبنى على Northflank باستخدام Docker.

## ملفات المشروع

- `server.js`: ملف الخادم الأصلي، نُسخ دون تعديل لأنه مموَّه ويحتاج مراجعة وظيفية قبل إعادة كتابته.
- `data.js`: يوفّر `token` و`id` للكود القديم، لكنهما يُقرآن من متغيرات البيئة بدل حفظهما في المستودع.
- `Dockerfile`: يبني صورة Node.js 22 ويشغّل `npm start`.
- `.github/workflows/check.yml`: يفحص صياغة JavaScript عند كل push أو pull request.

## إعداد GitHub

أنشئ مستودعًا جديدًا، ويفضّل أن يكون خاصًا، ثم ارفع محتويات هذا المجلد إليه. لا ترفع رمز البوت أو أي ملف `.env`. ملف `.gitignore` يستبعد ملفات البيئة والاعتماديات المحلية.

## النشر على Northflank

1. أنشئ خدمة جديدة واربطها بمستودع GitHub.
2. اختر البناء باستخدام `Dockerfile` الموجود في جذر المستودع.
3. عرّف منفذ الخدمة `8999` كبروتوكول HTTP، واجعله عامًا إذا كان مطلوبًا الوصول إلى الخادم من الإنترنت. إذا كانت الخدمة تستخدم WebSocket، انشره عبر الخدمة/المنفذ نفسه بعد التأكد من مسار الاتصال الذي يتوقعه الكود.
4. أضف متغيري البيئة التاليين في إعدادات الخدمة، واجعل قيمة الرمز سرًا محميًا:
   - `TELEGRAM_BOT_TOKEN` — رمز بوت تيليغرام الجديد.
   - `TELEGRAM_ADMIN_ID` — معرّف المدير.
5. انشر الخدمة وتابع سجلات البناء والتشغيل. المسار `/` موجود في الكود الأصلي ويُستخدم كفحص يدوي أولي.

يُفضّل اختبار نشر خاص أولًا. لم يتم تشغيل `server.js` أثناء إعداد هذه الملفات، لأن الكود مموَّه بشدة ولا يمكن اعتماد سلامته من مجرد تغليفه بـ Docker.

## تشغيل محلي

استخدم Node.js 22، ثم نفّذ `npm ci` وعرّف المتغيرين أعلاه في بيئة التشغيل، وبعد ذلك نفّذ `npm start`. لفحص الصياغة فقط، استخدم `npm run check`.

احتفظت ببيانات الاسم والوصف والمؤلف من ملف `package.json` الجديد، لكن لم أستخدم Node.js 16.13.2 أو إصدارات Multer وAxios وUUID القديمة: Node.js 16 لم يعد مدعومًا، كما كشف فحص الاعتماديات عن ثغرات في بعض الإصدارات المرفقة. استُخدمت نسخ أحدث وقُفلت في `package-lock.json`.

## تنبيه أمني مهم

الملف `data.js` المرسل سابقًا احتوى رمز بوت حقيقيًا كنص صريح. يجب إبطال ذلك الرمز من BotFather وإنشاء رمز جديد قبل أي تشغيل؛ لا تستخدم الرمز القديم. لا تحفظ الرمز الجديد في `data.js` أو GitHub، بل أضفه كمتغير بيئة/سر في Northflank.

`server.js` طويل ومموَّه عمدًا. هذا الإعداد يجهّز البناء والنشر فقط ولا يعني أن منطق التطبيق خضع لتدقيق أمني. راجعه أو اطلب من مطوّر موثوق فكّ تمويهه قبل تشغيله على خادم عام.
